# Пограничные случаи

Пограничный случай — любое место, где правила скилла сами по себе не определяют результат. До действия его
нужно показать пользователю с вариантами решения (рекомендуемый первым) и дождаться ответа. Всё, что не
упомянуто здесь, но подходит под это определение, — тоже пограничный случай.

Если пользователь принял решение, которое повторится в других компонентах, допиши его в журнал
[«Решено»](#решено) внизу файла: что за случай, что решили, почему, дата. Следующий компонент применяет журнал
без вопросов.

**Решение через токен Foundation или хардкод записывается и в журнал мест**, сразу как применено в Figma: в
`DEV-HANDOFF.md` (для разработчиков) или в `HARDCODED.md`. У вариантов ниже это помечено как
**→ DEV-HANDOFF** и **→ HARDCODED**. Правила и команды — в [registries.md](registries.md).

## Окружение и ветки

### Нет коллекций или работа в main
**Признак:** upsert отвечает `collection "theme" is missing`, или пользователь даёт ссылку на основной файл.
**Почему важно:** коллекция, созданная в ветке, при мёрже становится дублем.
1. **Рекомендуется:** дизайнер отдельной задачей запускает подготовку main
   ([figma.md](figma.md#подготовка-main-один-раз)) и сам обновляет ветку из main. Ты только объясняешь, что
   нужно, и ждёшь.
2. Для тестовой ветки, которую никогда не будут мёржить, создать коллекции прямо в ней через `bootstrap` с ключом
   ветки. Только если пользователь сам так сказал.

### Токены другого компонента ещё не в main
**Признак:** флаг `link-cross-widget`, в upsert проблема `link target … does not exist`, или компонент рисует
часть другого (кнопки DropDownButton — это токены `button`).
1. **Рекомендуется:** попросить дизайнеров смёржить ветку того компонента и обновить эту ветку из main. Сам ты
   этого не делаешь, а ждёшь.
2. Отложить части, которым нужны чужие токены, и доделать их после мёржа.

Создавать чужие токены в своей ветке нельзя: при мёрже будут дубли.

## Значения

### Значение без токена
**Признак:** Figma нужно значение, а у компонента нет токена. Например, размер шрифта и гарнитура текста
наследуются от `.dx-widget`: `font-size: var(--dxds-font-size-base-md)`, `font-family: var(--dx-global-font-family)`.
Сюда же относится любое поле, которое в CSS задано правилом с сырым `var(--dxds-*)`.
1. **Рекомендуется:** общий токен, если он есть: `font-size` (`--dx-font-size`: base-md / base-sm), `global/font-family`,
   `global/line-height`. Общие токены создаются при подготовке main.
2. Переменная Foundation напрямую — только для значения, которое одинаково в default и compact.
   Переключиться по режиму `size` она не может. **→ DEV-HANDOFF**
3. Оставить без привязки, если значение Figma передать не может (см. «Ключевые слова»). Если оставленное
   значение не совпадает со значением Figma по умолчанию, **→ HARDCODED**.

### `calc()`
**Признак:** флаг `literal:calc`. Пример — `button/content-padding` = `(height − icon − 2·border) / 2`.
1. **Рекомендуется:** посчитать для каждого режима. Если результат совпадает со ступенью Foundation, сделать
   алиас и записать формулу в описание переменной. Для `button/content-padding`: default (32 − 20 − 2) / 2 = 5 →
   `spacing-50`, compact (24 − 16 − 2) / 2 = 3 → `spacing-30`. В спецификации:
   `"values": { "default": { "ds": "spacing-50" }, "compact": { "ds": "spacing-30" } }`. **→ DEV-HANDOFF**
2. Если ступени нет — сырое число для каждого режима (`{ "value": 5 }`) с формулой в описании. **→ HARDCODED**
3. Не создавать токен и задать значение полю напрямую. Это хуже: значение выпадает из системы. **→ HARDCODED**

### `color-mix()` и цвет с прозрачностью
**Признак:** флаг `literal:color-mix`, например `color-mix(in srgb, var(--dxds-color-bg-inverted) 5%, transparent)`.
1. **Рекомендуется:** найти семантическую роль Foundation с тем же цветом и прозрачностью (ряды `*-alpha-*`) и
   сделать алиас на неё. **→ DEV-HANDOFF**
2. Значение-алиас с прозрачностью: `{ color: alias, opacity: 5 }`. Plugin API это поддерживает, но сначала
   проверь на одной переменной, что значение записалось. **→ DEV-HANDOFF**
3. Сырой RGBA — только с согласия пользователя. **→ HARDCODED**

### Ключевые слова: `normal`, `none`, `auto`
**Признак:** флаг `literal:keyword`.
1. **Рекомендуется:** токен не создавать, поле оставить в значении Figma по умолчанию и упомянуть в отчёте:
   - `line-height: normal` у текста — **исключение, см. «Решено» 2026-10-14**: компонентный токен
     `<префикс>/text-line-height` с алиасом `line-height/base-md` / `base-sm` → DEV-HANDOFF;
   - `letter-spacing: normal` → 0;
   - `text-transform: none` → регистр как есть.

   Переменная такое значение принять не может. В журналы не записывается.
2. Если ключевое слово влияет на вид, например `text-transform: uppercase`, — выставить поле вручную и отметить.
   **→ HARDCODED**

### Числа без пары: unitless, `em`, `0`
**Признак:** флаг `literal:number`.
- Unitless `line-height` переводится в px умножением на размер шрифта режима: 1.428571 × 14 = 20 →
  `line-height-base-md`; 1.3333 × 12 = 16 → `line-height-base-sm`. **Рекомендуется** алиас, если совпало.
- `em` переводится в px от размера шрифта элемента. Если совпало со ступенью — алиас, иначе сырое число.
- Алиас на ступень Foundation **→ DEV-HANDOFF**, сырое число **→ HARDCODED**.
- `0` — `spacing-0` / `border-width-0`. Если тема публикует токен со значением 0, его создают и привязывают (см. журнал, 2026-10-15). Сырой 0 без токена в CSS привязки не требует.

### Непрочитанный токен (`unread`)
**Признак:** флаг `unread`. Тема публикует токен, но правило берёт значение напрямую. Так у Button сделаны
отступы: `button/padding-inline` есть, а `.dx-button-has-text .dx-button-content` использует `var(--dxds-spacing-120)`.
1. **Рекомендуется,** если значение токена совпадает с тем, что видно в демке: привязать к токену. Кит
   документирует намерение, а значение то же.
2. Если не совпадает — показать расхождение и спросить. Возможно, это баг темы, и тогда в отчёт.

### Составные значения: `box-shadow`
**Признак:** флаги `composite` и `effect`. Тень из двух слоёв одной переменной не выразить.
1. **Рекомендуется:** применить к узлу стиль эффекта библиотеки `shadow/<size>` из Foundation tokens (`shadow/xs` …
   `shadow/2xl` соответствуют `--dxds-box-shadow-<size>`). Токен-переменную не создавать, в описании компонента
   указать `--dx-…-box-shadow`. **→ DEV-HANDOFF**
2. Собрать эффект вручную и привязать поля к переменным `box-shadow/layer-{1,2}-{x,y,blur,spread,color}-<size>`
   (рецепт в [figma.md](figma.md#рецепты-привязок)). **→ DEV-HANDOFF**

### У `--dxds-*` нет пары в Figma
**Признак:** флаг `no-figma-counterpart` или `unresolvedDs` в ответе upsert (`font-family-system-*`, `text-case-*`,
`icon-color-*`).
1. **Рекомендуется:** ближайшая переменная Foundation по смыслу, например `font-family/sans-serif`, — показать её
   пользователю. **→ DEV-HANDOFF**
2. Сырое значение, только с согласия. **→ HARDCODED**

### Значение зависит от режима или размера
**Признак:** флаг `mode-dependent` (светлая ≠ тёмная) или `size-dependent-colour`.
Ни то, ни другое для Fluent Next не ожидается. Покажи оба значения и найди, какое правило темы их разводит. Не
добавляй режимы в `theme`, не согласовав это с пользователем.

### Токен переобъявлен под другим селектором
**Признак:** флаг `multi-value`.
**Рекомендуется:** в переменную идёт базовое значение, с корня виджета. Переобъявление относится к контексту
другого компонента (например, кнопка внутри toolbar). Здесь его упомянуть, а учитывать при работе над тем
компонентом.

### Токена нет в собранном CSS
**Признак:** флаг `missing-in-css`. Пересобери бандл (`pnpm run demos:prepare`). Если токена всё равно нет,
значит он мёртвый: пропусти и напиши в отчёте.

### Виджет визуализации (viz): цвета в JS-теме
**Признак:** `component-tokens.mjs <widget>` отвечает `unknown widget`. Это Bullet, Sparkline, Chart и другие
виджеты из `js/__internal/viz`. Их стили живут не в SCSS, а в `viz/core/themes/fluent-next/index.ts`, в секции
виджета: `bullet: { color: paint(VIZ_BLUE), … }`. `paint()` даёт `var(--dx-viz-*)`. Токены кита — эти
`viz/*`. Одни лежат в спеке `viz`, другие (`viz/content`, `viz/bg`, …) — в спеке `common`. Собери нужные в
одну спеку и запусти upsert. Размеры (`targetWidth`, отступы, доли высоты) — опции и константы JS, CSS-токенов
у них нет. Оставь их числами и сделай информационную запись в HARDCODED. Геометрию снимай в демке с
`getBoundingClientRect` путей SVG: `sharp()` сдвигает линии толщиной 1 на 0,5px.

## Компонент

### Опция API не ложится на свойство однозначно
**Признак:** значение опции не является простым перечислением. Например, CheckBox `value: boolean | null`, где
`null` — indeterminate.
1. **Рекомендуется:** строго по API — `value=true|false|null`.
2. По словарю состояний темы — `value=checked|unchecked|indeterminate`. Это отступление от правила «строго по
   API», только с согласия.

### Состояние: есть в теме, нет в компоненте, или наоборот
**Признак:** у кнопки есть токены `*-selected`, но выбранной она бывает только внутри ButtonGroup. Или в ките есть
состояние, которое тема не стилизует.
1. **Рекомендуется:** включить состояние, если у него есть токены или правила темы. Тогда составные компоненты
   (ButtonGroup) строятся из инстансов.
2. Не включать, оставить на уровне составного компонента.

Состояние, которое тема не стилизует, убирается. Сначала перенеси его инстансы на другое состояние.

### Фокус
**Признак:** у темы есть токены `focus-rect/*` (толщина, отступ, радиус рамки), а класс `dx-state-focused` даёт
только фон. Рамка появляется при фокусе с клавиатуры. Сначала посмотри её в демке (Tab, см.
[demos.md](demos.md#состояния)).
1. **Рекомендуется:** в варианте `state=focused` нарисовать рамку внутри компонента. Это дочерний слой
   `focus-rect` с абсолютным позиционированием и обводкой по токенам `focus-rect/*`. Лишней обёртки в инстансах
   не появляется.
2. Отдельный примитив-обёртка, как Focus Rect в vNext UI Kit.

### Существующая ось вариантов не из API
**Признак:** в ките есть ось, которой нет в API. Например, у Button
`Content=Icon + Text|Text Only|Icon Only` вместо `hasText` и `hasIcon`. Переделка — это миграция с риском для
инстансов. Покажи соответствие старых значений новым, число затронутых инстансов по страницам и порядок
миграции из [figma.md](figma.md#как-править-набор-компонентов-не-ломая-инстансы). Делай только после «да».

### Переопределения в инстансах
**Признак:** в аудите, в `instances.overrides`, есть `paint`, `size` или `font`. Самый частый источник — подмена
иконки: Figma копирует цвет глифа в инстанс как сырое значение (у Button таких 435). Сырое переопределение
сильнее привязки в мастере. Такой инстанс не пойдёт за токеном и в тёмной теме останется со старым цветом.
Фиксированный размер не даёт работать режиму `compact`. Переопределённый шрифт не следует за токенами текста.
1. **Рекомендуется:** где переопределение совпадает со старым значением мастера, сбросить его или привязать к
   тому же токену, что в мастере. Где оно осмысленное (другой размер в чужом контексте), оставить и назвать.
2. Цвет иконки сделать маской: глиф служит маской для слоя с цветом по токену. Тогда цвет не зависит от
   подмены иконки, но меняется структура иконки во всех вариантах.
3. Не трогать сейчас и перечислить в отчёте.

### Инстансы внутри мастеров других компонентов
**Признак:** в аудите, в `instances.insideOtherComponents`, указано, в мастерах каких компонентов лежат инстансы
(у Button это `.HtmlEditor Toolbar`, `Calendar`, `Popup` и др.). Правка этих инстансов — правка того компонента.
У него может быть своя открытая ветка, и тогда при мёрже будет конфликт.
1. **Рекомендуется:** в своей ветке менять только то, без чего инстансы сломаются (миграция удаляемого
   варианта). Остальное — привязки, сброс переопределений — перечислить для веток тех компонентов. Спросить,
   не открыты ли у них ветки сейчас.
2. Править всё в своей ветке, если пользователь подтвердил, что веток тех компонентов нет.

### Изменение ломает инстансы
**Признак:** удаление слоя или варианта, у которого есть инстансы или переопределения. Покажи, где они, и как
сохранишь переопределения. Предпочтительный путь — правка на месте.

### Демка расходится с токенами
**Признак:** вычисленный стиль в демке не равен значению токена.
1. **Рекомендуется:** собрать так, как в демке, — это видит пользователь. Расхождение указать в отчёте как
   возможный баг темы. Если значение демки не выражается токеном, **→ HARDCODED**.
2. Собрать по токену, если пользователь считает баг в демке.

### Иконки
Иконки кита — локальные компоненты на странице Icons (`favorites`, `add`, …). Если демка показывает иконку,
которой в ките нет, не рисуй её: спроси. Размер иконки привязывается к токену размера компонента, цвет — к
переопределению заливки глифа.

## Решено

Журнал повторяющихся решений. Новые записи добавляются в конец.

- **2026-10-08 — основы кита.** Решения 1–6 из SKILL.md: имена токенов, коллекции и режимы (`theme`:
  `fluent-next`; `size`: `default`/`compact`), значения-алиасы, свойства строго по API в нижнем регистре,
  `state` одной осью, части как классы-модификаторы DOM, слои по DOM без лишних блоков. Аннотации Utils
  перегенерируют дизайнеры своим плагином.
- **2026-10-08 — ветки.** Ветки создают, обновляют из main и мёржат дизайнеры, задачи они запускают явно. Агент
  только говорит, что нужно сделать с ветками.
- **2026-10-08 — `boolean | null` (CheckBox `value`).** Значения строго по API: `value=true|false|null`, без словаря
  `checked|unchecked|indeterminate`.
- **2026-10-08 — валидация редакторов.** Отдельная ось `validationStatus` (не внутри `state`). В ней значения API,
  которые тема стилизует: у CheckBox `valid|invalid`, `pending` — только там, где у него есть свой вид. Сетка
  полная: invalid × read-only/disabled — копии с привязками обычных read-only/disabled, так каскадит CSS.
- **2026-10-08 — размеры в `em`.** Перевести в px от font-size элемента и сделать алиас на ступень `spacing/*`,
  формулу записать в описание переменной. Scope — по полю Figma, к которому идёт привязка: размер глифа —
  ширина/высота.
- **2026-10-08 — начертание текста без токена компонента** (`.dx-widget { font-weight: 400 }`). Привязка
  напрямую к Foundation `font-weight/base-default`. Это согласованное исключение из правила «только через токены
  компонента», аудит покажет его в `library`.
- **2026-10-08 — значения по умолчанию у boolean-частей.** Как в API: `hasText=false` при `text: ""`. Инстансам,
  которые показывают часть, значение выставляется явно.
- **2026-10-08 — баги кита чиним**, даже если инстансы сдвигаются на несколько пикселей. Пример — лишний отступ
  у CheckBox без подписи (24×16 → 16×16). Сдвиг называется в отчёте.
- **2026-10-08 — текстовый элемент с отступами** (`.dx-*-text` с padding). Фрейм с именем класса: отступы по
  токенам, видимость ↔ `has…`. Внутри — существующий текстовый слой `text`, перенесённый, а не пересозданный:
  переопределения инстансов сохраняются.
- **2026-10-08 — журналы мест.** Решения через токен Foundation записываются в `DEV-HANDOFF.md` для
  разработчиков, хардкод — в `HARDCODED.md`. Скилл делает это сам и сразу пушит. Одно место — одна строка.
- **2026-10-08 — коллекции и общие токены в первой ветке (Button).** Main не подготовлен, поэтому коллекции
  `theme`/`size` и общие токены `font-size`, `global/font-family` создали прямо в ветке Button. Пока она не
  смёржена, в других ветках их не создавать: ждать мёржа и «Update from main».
- **2026-10-08 — стиль тени Foundation (`shadow/<size>`) в DEV-HANDOFF не пишется.** Применение стиля эффекта
  вместо `--dx-…-box-shadow` — штатный путь, а не отступление.
- **2026-10-08 — вариант по умолчанию не бывает пустым.** Если значения API по умолчанию дают пустой компонент
  (у Button `text: ""` и `icon: ""`), по умолчанию показывается текст: `hasText=true`, `hasIcon=false`, текст
  «Button».
- **2026-10-14 — сабкомпоненты делаются на странице «Subcomponents».** Набор переносится туда со старой
  «Sub-components» и пересобирается на месте (см. [checklist.md](checklist.md)).
- **2026-10-14 — `labelMode=floating` у `.Label` рисует пустое поле** (label внутри поля, крупный). Floating со
  значением неотличим от static, для него используется `static`. Отдельной оси `empty` у `.Label` нет.
- **2026-10-19 — у `.TextEditor` заполненность — вариантное свойство `hasValue=false|true`** (класс
  `dx-texteditor-empty`). Она меняет раскладку: при значении плейсхолдер скрыт, а значение стоит на его месте.
  Floating-подпись поднимается на рамку, как в focused, и берёт `.Label` `labelMode=static`. Boolean так не
  умеет: слои показывались рядом, а подпись оставалась внутри. Вариантов 240. `hasPlaceholder` действует только
  при `hasValue=false`.
- **2026-10-19 — окно в рамке outlined под подписью закрывает полоска `label-box › label-backdrop`.** Её высота —
  `text-editor/label-backdrop-height` (3px), заливка — `text-editor/outlined-bg`, ширина — подпись. Заливку у
  `.Label` внутри `.TextEditor` не ставить. В коде это разрыв `border-top` без фона, поэтому полоска видна только
