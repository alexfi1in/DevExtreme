# Журналы решений: DEV-HANDOFF.md и HARDCODED.md

Каждый решённый пограничный случай, после которого в ките осталось значение не из компонентного токена,
попадает в один из двух журналов. Скилл ведёт их сам и пушит сразу, как чек-лист (тем же механизмом — см.
[checklist.md](checklist.md)).

| Журнал | Что в него идёт | Для кого |
|---|---|---|
| [DEV-HANDOFF.md](../DEV-HANDOFF.md) | случай решили **через токен Foundation** | разработчикам: где код темы выражает значение не через дизайн-токен, и что предлагаем |
| [HARDCODED.md](../HARDCODED.md) | случай решили **хардкодом** | всем: места вне системы токенов, которые со временем нужно убрать |

## Куда записать решение

| Решение | Журнал |
|---|---|
| Компонентный токен стал алиасом Foundation, а в коде у него `calc()`, `em`, unitless, `color-mix()` или литерал (`button/content-padding` → `spacing/50`/`spacing/30`; `check-box/arrow-font-size` 0.75em → `spacing/120`) | DEV-HANDOFF |
| Поле привязано к переменной Foundation напрямую, потому что токена компонента нет (`font-weight/base-default` у текста) | DEV-HANDOFF |
| Применён стиль эффекта Foundation (`shadow/xs` вместо `--dx-…-box-shadow`) или поля эффекта привязаны к `box-shadow/layer-*` | DEV-HANDOFF |
| У `--dxds-*` нет пары в Figma, взяли ближайшую переменную Foundation | DEV-HANDOFF |
| В переменной сырое значение (`"value": …` в спецификации) | HARDCODED |
| Поле оставлено без привязки по решению, и аудит показывает его непривязанным (начертание Regular без токена, отступ числом) | HARDCODED |
| Значение выставлено вручную, потому что в Figma для него нет поля-переменной (например, `text-transform: uppercase` → регистр текста) | HARDCODED |
| Решили через компонентный или общий токен (ссылка на другой `--dx-*`, `font-size`, `global/font-family`) | никуда |
| Поле оставлено в значении Figma по умолчанию, совпадающем с CSS (`line-height: normal` → Auto, `letter-spacing: normal` → 0) | никуда |

- **Одно место — одна строка**, даже если правило решения взято из журнала «Решено» в
  [edge-cases.md](edge-cases.md). Журнал «Решено» хранит правила, а эти два журнала — конкретные места.
  Например, начертание текста без токена решено один раз для всех компонентов, но каждый компонент добавляет
  свою строку в DEV-HANDOFF.
- **Записывай сразу, как применил решение в Figma** (шаги 5–6), не дожидаясь конца работы. Так запись не
  потеряется, если работа прервётся.
- **На шаге проверки сверь аудит с журналами.** Каждая оставшаяся непривязанной группа и каждая привязка
  `library` должна иметь строку в HARDCODED или DEV-HANDOFF. Если строки нет, значит пропущено решение.

## Команды

```bash
R=.claude/skills/fluent-next-ui-kit/scripts/registry.mjs

node $R add foundation --component CheckBox --where "check-box/arrow-font-size" \
  --code '`--dx-check-box-arrow-font-size: 0.75em` (.dx-checkbox-icon::before, font-size)' \
  --value '`spacing/120` (12px)' \
  --why 'выразить через var(--dxds-spacing-120) или опубликовать токен размера глифа' \
  --branch <ссылка на Figma-ветку>

node $R add hardcoded --component Button --where "button/content-padding" \
  --value 'default 5, compact 3' --code '`calc((height - icon-size - 2·border) / 2)`' \
  --why 'нет ступени Foundation для этой формулы' --todo 'токен или ступень spacing с готовым значением' \
  --branch <ссылка на Figma-ветку>

node $R list                         # оба журнала
node $R list hardcoded --open        # только открытые
node $R list --component CheckBox    # записи одного компонента
node $R resolve foundation 3 --note "тема переведена на var(--dxds-spacing-120)"
```

- **`--where`** — место в Figma: имя переменной (`check-box/arrow-font-size`) или слой и поле
  (`text › fontWeight`, `(root) › effects`). Пара «компонент + место» — ключ строки. Повторный `add` того же
  места обновляет строку, а не добавляет новую.
- **`--code`** — что в коде темы: токен и его значение, а для поля без токена — селектор и CSS-свойство (они
  есть в колонке «read by» таблицы `component-tokens.mjs`).
- **`--why`** — в DEV-HANDOFF это предложение разработчикам, в HARDCODED — почему не токен.
- **`--todo`** (только HARDCODED) — что нужно, чтобы убрать хардкод.
- **`resolve`** ставит «✅ сделано» и пишет итог. Его вызывают, когда разработчики поправили тему или хардкод
  заменили токеном, — по слову пользователя.
- **`init`** создаёт оба файла, если их нет. `--local` работает только с локальными файлами, без git.

В отчёте (шаг 8) перечисли строки, которые добавил в оба журнала.
