# Чек-лист компонентов

[CHECKLIST.md](../CHECKLIST.md) задаёт порядок работы над компонентами кита и показывает, кто что делает.
Скилл ведёт его сам: проверяет перед работой, отмечает «в работе» и «на ревью» и сразу пушит. Так дизайнеры,
работающие параллельно, видят одно и то же состояние.

## Как устроен

- **Строка = компонент = одна Figma-ветка.** Это страница кита (Button, CheckBox, DataGrid…). Наборы со
  страницы Sub-components (`.TextEditor`, `.Label`, `.SpinButtons`, `.DropDownButton`, `.Tag`, `.Badge`,
  `.Informer`, `.Separator`) идут отдельными строками: их используют многие редакторы.
- **Порядок — снизу вверх по зависимостям.**
  - Уровень 0 — компоненты, внутри которых нет других компонентов кита.
  - Компонент уровня N собран из компонентов уровней ниже.
  - Внутри уровня выше стоят те, что чаще используются внутри других.
  - Компоненты одного уровня можно делать параллельно.
- **Компонент готов к работе, когда всё из колонки «Состоит из» смёржено.** Если работа начинается раньше,
  чужие части внутри компонента останутся старыми. Это пограничный случай.
- **Статусы:**

  | Статус | Ключ | Когда ставится | Кто ставит |
  |---|---|---|---|
  | ⬜ не начат | `todo` | изначально или при отказе от работы | — |
  | 🟦 в работе | `in-progress` | сразу после одобрения плана | агент, с веткой и именем |
  | 🟨 на ревью | `review` | после отчёта | агент |
  | ✅ смёржен | `merged` | когда дизайнер смёржил ветку | дизайнер или агент по его словам |
  | ⛔ заблокирован | `blocked` | работа упёрлась во внешнее, причина в заметке | агент |

## Команды

```bash
C=.claude/skills/fluent-next-ui-kit/scripts/checklist.mjs
node $C show Button                     # статус компонента и готовность его зависимостей
node $C show                            # сводка: сколько в каждом статусе, что в работе
node $C next                            # что можно брать в работу, в порядке чек-листа
node $C set Button in-progress --branch <ссылка на Figma-ветку>
node $C set Button review --note "38 токенов, 36 вариантов; аннотации Utils перегенерировать"
node $C set Button merged
node $C set Button blocked --note "ждёт мёржа .TextEditor"
```

- **`set` сразу пушит.** Скрипт забирает свежую удалённую ветку, меняет одну строку и коммитит поверх неё
  plumbing-командами. Твоя рабочая копия, индекс и текущая ветка не трогаются. Если кто-то запушил раньше,
  скрипт повторяет попытку на свежем состоянии.
- **Куда пушит.** В upstream текущей ветки, то есть в форк, где лежит скилл. Другую цель задают
  `UI_KIT_CHECKLIST_REMOTE` и `UI_KIT_CHECKLIST_BRANCH`. В `github.com/DevExpress/DevExtreme` скрипт пушить
  отказывается.
- **`show` и `next` читают удалённую версию**, а не локальный файл: он мог отстать.
- **`--local`** работает только с локальным файлом, без git. Это для проверок и для копии, где нет форка.
- **`set … in-progress` по компоненту, который уже в работе по другой ветке, скрипт отклоняет.** Это значит, что
  им уже занимается кто-то другой: спроси пользователя. `--force` забирает строку только по его прямому слову.

## Когда что делать

| Момент | Действие |
|---|---|
| Шаг 1 (предполётная проверка) | `show <компонент>`. Компонент «в работе» с другой веткой — остановись и спроси. Не все зависимости смёржены — пограничный случай, назови, каких не хватает. |
| План одобрен, до первой правки в Figma | `set <компонент> in-progress --branch <url ветки>` |
| Отчёт готов (шаг 8) | `set <компонент> review --note "<одна строка: что сделано, что осталось>"` |
| Пользователь говорит, что ветка смёржена | `set <компонент> merged` |
| Работа встала из-за внешнего | `set <компонент> blocked --note "<чем>"` |
| «Что брать дальше?» | `next`: перечисли первые позиции с их зависимостями. Ветку под выбранный компонент создаёт дизайнер. |
| Пуш не прошёл (нет upstream, нет прав, сеть) | Скажи пользователю, что именно не прошло. Не меняй remote и не пушь в другое место сам. |

## Пересборка чек-листа

Когда в ките появляются новые компоненты или меняется их состав, граф строится заново. Это отдельная задача,
которую дизайнер запускает явно, например «обнови чек-лист».

1. **Код скрипта графа.** Сгенерируй его для main кита:

   ```bash
   node .claude/skills/fluent-next-ui-kit/scripts/figma-code.mjs graph --file-key DpK8J5xUCl7Gc70DKC4I1K
   ```

2. **Граф.** Выполни этот код через `figma_execute`. Скрипт только читает. Сохрани ответ (`{file, fileKey,
   generatedAt, items}`) в `<scratchpad>/graph.json`.
3. **Чек-лист.** Пересобери его:

   ```bash
   node .claude/skills/fluent-next-ui-kit/scripts/checklist.mjs build --graph <scratchpad>/graph.json
   ```

   Статусы, ветки, имена и заметки сохраняются. Новые компоненты встают на своё место в порядке. Строки,
   которых больше нет в ките, переезжают в раздел «Больше нет в ките».
